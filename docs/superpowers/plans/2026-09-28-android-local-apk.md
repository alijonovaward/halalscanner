# Android Local APK Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build an installable HalalScan debug APK that loads the Laravel interface from this Mac over local Wi-Fi and uses the official Capacitor native barcode scanner on Android.

**Architecture:** Add a separate Capacitor 8 project under `mobile/`, while the Laravel/Vite application remains the remote UI. The backend bundle detects the Android Capacitor bridge and delegates barcode capture to `@capacitor/barcode-scanner`; ordinary browsers retain the existing live-camera/photo fallback. A build-time configuration script embeds one validated backend origin and generates a local retry page.

**Tech Stack:** Capacitor 8.5.2, `@capacitor/barcode-scanner` 3.1.2, Node.js 22, Android SDK 36, Gradle/AGP generated by Capacitor 8, Java 17, ML Kit.

**Spec:** `docs/superpowers/specs/2026-09-25-container-android-staging-design.md`

## Global Constraints

- Application name is `HalalScan`; application identifier is `uz.halalscan.app`.
- Minimum Android SDK is 26.
- The first deliverable is an unsigned debug APK; Play publication and production signing are out of scope.
- The APK loads one build-time `HALALSCAN_SERVER_URL`; do not add wildcard navigation origins.
- HTTP cleartext is permitted only in the debug manifest for local Wi-Fi testing. A later staging build must use HTTPS.
- The official barcode plugin uses the rear camera, adaptive orientation, and ML Kit.
- The plugin accepts only one format hint, so request `ALL` and then accept only EAN-13, EAN-8, UPC-A, UPC-E, Code 128, and ITF results that normalize to 8–14 digits.
- Cancellation changes nothing and shows no error. Permission or scanner failures preserve manual barcode entry and show a concise Russian error.
- Gemini credentials and ingredient images remain server-side/in request memory; the APK contains no provider credentials.

## Review Focus

- A changed or unreachable Mac LAN address must lead to the bundled error page with a retry action, not a permanent blank screen (Task 2 configuration tests and Task 3 offline launch check).
- Native scan cancellation must leave the current barcode untouched and not start a catalog request (Task 1 unit test).
- Permission denial or plugin failure must keep manual entry usable and display a Russian error (Task 1 unit and integration tests).
- Unsupported formats, non-digits, and values outside 8–14 digits must never auto-submit (Task 1 unit tests).
- Local HTTP must be enabled only for debug builds; release/staging configuration must not expose cleartext or wildcard navigation (Task 2 configuration and manifest checks).

### Task 3: Build and hand off the local-network debug APK

**Files:**
- Create: `mobile/README.md`
- Build artifact: `mobile/android/app/build/outputs/apk/debug/app-debug.apk` (ignored, not committed)

**Interfaces:**
- Consumes: the Mac's active LAN IPv4 address and a Laravel server listening on `0.0.0.0:8000`.
- Produces: an installable debug APK configured for the resolved `http://${lan_ip}:8000` origin plus exact start/install instructions.

- [ ] **Step 1: Resolve and verify the current LAN backend URL**

Determine the active Wi-Fi/Ethernet IPv4 address without hard-coding it in tracked files:

```bash
default_interface="$(route -n get default | awk '/interface:/{print $2}')"
lan_ip="$(ipconfig getifaddr "$default_interface")"
server_url="http://${lan_ip}:8000"
curl --fail "$server_url/up"
```

If no server is reachable, start the Laravel backend with `php artisan serve --host=0.0.0.0 --port=8000` without interrupting unrelated listeners.

- [ ] **Step 2: Write the operator handoff**

Document how to start the local backend, rebuild for a changed LAN IP, run `adb install -r`, find the APK, keep phone and Mac on the same Wi-Fi, and interpret the retry page. State that local HTTP is debug-only and the next staging build will use HTTPS.

- [ ] **Step 3: Sync against the real LAN URL and run all mobile gates**

Run:

```bash

HALALSCAN_SERVER_URL="http://${lan_ip}:8000" HALALSCAN_BUILD_PROFILE=debug npm run android:sync
node --test tests/*.test.mjs
cd android
./gradlew testDebugUnitTest lintDebug assembleDebug
```

Expected: tests and lint pass and `app-debug.apk` is produced.

- [ ] **Step 4: Inspect the APK contract**

Use the installed Android SDK build tools to confirm package `uz.halalscan.app`, debug signing, minimum SDK 26, camera/internet permissions, and non-empty APK size. Confirm generated Capacitor assets contain the current LAN URL and no Gemini/database credentials.

- [ ] **Step 5: Install when an Android device is connected**

Run `adb devices`. If exactly one authorized device is available, install with `adb install -r`; otherwise keep the verified APK for manual transfer and report its absolute path.
